# No-Cron — React frontend

Visual workflow builder for event-driven AWS automations. React 18 + Vite +
Tailwind + Recoil, with React Flow arriving in Phase 2.

## Run it

```bash
npm install
npm run dev
```

## Phase 1 — app shell and store

- App shell: top bar, node library, canvas surface, inspector, status bar.
- Design tokens in `tailwind.config.js` — one place to shift the palette. Now a
  paper/drafting-table theme: warm stone background, hairline borders, grain
  texture, steel/plum/brass accents instead of the original dark neon pass.
- `src/lib/nodeCatalog.js` — every block type, its icon, AWS service label and
  default `data` payload. Adding a block is a one-file change.
- Recoil store (`src/state/`): nodes, edges, selection, workflow metadata.
- `useWorkflow()` — the only path that mutates the graph.
- Click-to-add and drag-and-drop from the library onto the canvas.

## Phase 2 — real canvas, validation, deploy

- `CanvasSurface` now renders `<ReactFlow/>` for real: pan, zoom, a themed
  drafting-table grid (`<Background/>` layers, which pan/zoom with the graph
  instead of a fixed CSS background), and actual edge connections drawn by
  dragging from one handle to another.
- `FlowNode.jsx` — one generic custom node component for every catalog type.
  Handle layout is derived from `kind` (trigger / logic / action); the branch
  type gets two source handles, labeled True and Right for its Choice output.
  `NodeCard` is unchanged as the visual body.
- `lib/fieldSchemas.js` + `ConfigTab.jsx` — typed per-type form controls
  (select, number, textarea) with required-field markers and hints, replacing
  Phase 1's generic key/value iteration.
- `WebhookUrlField.jsx` — the generated `wh_xxxxxxxx` URL with copy-to-clipboard.
- Inspector output tabs (`components/inspector/tabs/`): **Backend Payload**
  (exact JSON "Deploy Workflow" would send), **AWS Step Functions JSON** (a
  simplified States Language document generated by walking the graph's
  edges), **Test Logs** (an honest empty state — no backend exists yet, so
  this doesn't fabricate run history).
- `lib/validator.js` — missing trigger, orphaned nodes, empty required fields,
  branch nodes missing a True or False path.
- `lib/serializer.js` — `buildDeployPayload` and `buildStateMachine`, both
  pure functions of `{meta, nodes, edges}` so the inspector tabs and the
  deploy hook share one source of truth.
- `state/useDeploy.js` — validates on click; on failure, `DeployBanner` lists
  every fix needed instead of just disabling the button silently. On success,
  simulates the round trip (swap the `setTimeout` for a real `fetch` once the
  Express API exists) and marks the workflow active.

## What's still a stub

- Deploy doesn't call a real API — `useDeploy.js` simulates the network call.
  Point it at your Express endpoint and send `buildDeployPayload(...)` as the body.
- Test Logs has no data source — wire it to `GET /api/workflows/:id/logs` and
  replace the empty state with a list of timestamp / status badge / payload rows.
- "Simulate Run" in the top bar isn't wired to anything yet.

## Structure

```
src/
  lib/
    nodeCatalog.js      block definitions, accents, defaults
    ids.js               node/edge/hook id minting, hookUrl()
    fieldSchemas.js       per-type inspector form schema
    validator.js          structural checks before deploy
    serializer.js          graph → deploy payload / Step Functions JSON
  state/
    atoms.js              Recoil atoms + selectors
    useWorkflow.js         all node/edge mutations (incl. React Flow handlers)
    useDeploy.js           validate → (simulated) deploy lifecycle
  components/
    layout/     AppShell, StatusBar
    topbar/     TopBar, DeployBanner
    library/    NodeLibrary, LibraryCard
    canvas/     CanvasSurface, FlowNode, NodeCard, nodeTypes.js
    inspector/  InspectorPanel, ConfigTab, WebhookUrlField, tabs/ CodeBlock.jsx PayloadTab.jsx StepFunctionsTab.jsx LogsTab.jsx 
    ui/         Button, Panel
```
